# Cartowords 実装仕様書(Unity / Claude Code向け)

> **ドラフトです。** 検討中の内容で、「仮」「未決」と書いた箇所は決まっていません。変更されることがあります。ライセンスは付けていません(すべての権利を保有します)。

この仕様書は、Cartowords の MVP を、Unity 単体で Claude Code が実装するための指示書です。

## 用語

この仕様書では、ノートを「ファイル」、町を「フォルダ」、リンクを「Edge」と書きます。島は、1 つのファイルの見出しの木を指します。

| 用語 | 意味 | この仕様書での呼び方 |
| --- | --- | --- |
| ノート | Markdown 1 つ。画面では、ファイルをノートと呼ぶ | ファイル(.md) |
| 町 | フォルダ。入れ子の深さは自由で、親も子もすべて町と呼ぶ | フォルダ |
| 見出し | エディタでの呼び名(# 〜 ###) | 同じ |
| 拠点 | マップでの見出し。立てると周りの土地が開く | Node |
| 島 | 1 つのノートの拠点のまとまり。見出しの親子の道でつながる | 見出しの木(ファイル単位) |
| 道 | リンク。拠点どうし、島どうしをつなぐ | Edge |
| 橋 | 町をまたぐ道。描き分けは MVP 後 | crossFolder が真の Edge |
| 孤島 | ほかの島と、道で 1 本もつながっていない島 | isolated |
| 暗闇 | 黒いレンガの壁。まだ何も書いていない領域 | 同じ |
| 開けた土地 | 拠点の周りに開く、書いた場所 | 同じ |
| 霧 | `?` や `TODO:` を書いた、まだ分からない場所 | Fog |
| 目印 | 道や拠点に付く小さな「!」。理由なし・リンク切れ・孤島の 3 つ | Mark |
| 花 | 感情語を書いた箇所に咲く。色と形が感情の種類を表す | Flower |
| 固有名詞のノート | 人名などを登録するノート。ノートの中に別名を書いておく | 同じ |
| 別名 | 固有名詞のノートに書く、本名やあだ名などの呼び方 | 同じ |
| 建物 | 別名が書かれた拠点に建つ。ダブルクリックで固有名詞のノートを開く | 同じ |
| 本文量 | 見出し直下に自分で打った文字数 | typedChars |
| 履歴 | 入力履歴ログ。打った操作の記録 | .jsonl |
| 来歴 | 各文字が「自分で打った」か「来歴不明」かの区別 | typed / unknown |

## 前提と技術構成

| 項目 | 内容 |
| --- | --- |
| エンジン | Unity 単体(使用中のバージョンに合わせる)。UI Toolkit のランタイム利用が前提 |
| 画面 | UI Toolkit で、エディタとファイル一覧を作る |
| マップ | 2D のドット絵風タイルマップ。描画方式(UI Toolkit のカスタム要素か、2D オブジェクトか)は M0 で決める |
| 対象 | デスクトップのみ。ネットワークなしで動く |
| 保存 | プロジェクトフォルダ内の .md と、入力履歴ログ |
| 開発運用 | Claude Code が Unity CLI を使って実装・テストし、受け入れ確認は開発者本人が行う |

**設計方針:** 入力履歴の処理、Markdown の解析は、Unity に依存しない C# のクラスとして別アセンブリに分ける。画面を起動しなくても EditMode テストで検証でき、Claude Code が自動で確かめながら進められる。

## データ設計

本文は素の Markdown のまま保存し、「自分で打った文字」の情報は別ファイルの入力履歴ログに持ちます。`notes/` の下のフォルダ階層は、そのまま町の階層として読みます。入れ子の深さは自由です。

```
MyProject/
  notes/
    大学用/
      授業/
        科目A/
          ノート.md       本文(素の Markdown)
    個人用/
  .cartograph/
    history/
      大学用/授業/科目A/ノート.jsonl   ノートごとの入力履歴ログ(1 行 = 1 イベント)
    settings.json         表示などの設定
```

**入力履歴ログの 1 行:**

```json
{"seq": 128, "t": 1761270000123, "type": "insert", "pos": 342, "text": "波", "src": "ime"}
```

| 項目 | 内容 |
| --- | --- |
| seq | ファイル内で 1 から増える通し番号 |
| t | 記録時刻(Unix ミリ秒) |
| type | insert(挿入)、delete(削除)、move(内部移動)、blocked(遮断した貼り付けの試行) |
| pos | 文字位置。C# の string と同じ UTF-16 単位で数える |
| text / len | insert は挿入した文字列。delete と move は対象の長さ len |
| src | key(キー入力)、ime(IME 確定)、internal(内部コピーの貼り付け)、undo(元に戻す・やり直し) |
| from | move と internal のとき、元の文字位置 |

**来歴の再構築:** 空の文書から履歴を先頭から再生し、各文字に「自分で打った(typed)」か「それ以外(unknown)」のラベルを持たせる。move と internal は元の文字のラベルを引き継ぐ。履歴のないノート、または履歴が本文と食い違うノートは、本文全体を unknown とする(落ちずに、来歴不明として扱う)。

**履歴の肥大化:** 1,000 イベントごとにスナップショット(本文とラベル列)を保存し、再生はそこから始める。

## 入力制御仕様

ペーストの経路ごとに遮断するのではなく、入力の結果として起きた文字の挿入を差分で判定し、説明のつかない挿入を巻き戻します。経路が増えても漏れにくくするためです。

**判定規則:** テキスト欄の値が変わるたびに、前の値との差分(挿入された文字列)を取る。次のいずれかで説明できる挿入は許可し、できないものは直前の状態に巻き戻して blocked を記録する。

1. 直前のキー入力で生じた 1 文字(src = key)
2. IME の変換確定で生じた文字列(src = ime)
3. 内部バッファと完全に一致する文字列(src = internal)
4. 元に戻す・やり直しの操作(src = undo)

| 操作 | 扱い |
| --- | --- |
| キーボードでの入力 | 許可 |
| IME の変換確定(日本語入力) | 許可。変換中の未確定文字は本文に反映されるまで判定しない |
| Ctrl/Cmd+V、右クリックの貼り付け | 外部のテキストなら遮断。内部バッファと一致するときだけ許可 |
| 外部からのドラッグ&ドロップ | 遮断(Unity の UI Toolkit が受け付ける場合のみ) |
| コピー、切り取り | 許可。OS のクリップボードへ書き出し、同じ内容をアプリ内の内部バッファにも保持する |
| ノート間の貼り付け | 内部バッファと一致すれば許可。元の文字のラベルを引き継ぐ |

**遮断時の表示:** エディタの上部に「外部からの貼り付けはできません」と短く表示し、2 秒で消す。入力そのものは妨げない。

## 解析仕様

解析は、行を上から順に読む単純な走査と正規表現で行います。コードブロック(`` ``` `` で囲まれた範囲)の中は解析しません。

| 対象 | 規則 | 出力 |
| --- | --- | --- |
| 拠点 | 行頭が `#`、`##`、`###` の見出し | Node(id はフォルダ付きの相対パスと見出しの階層から作る) |
| 本文量 | 見出しの直下から次の見出しの手前までのうち、ラベルが typed の文字。空白と改行は数えない。履歴のない文章は、すべて unknown として数えない | Node.typedChars |
| 道 | `[[ファイル名]]`、`[[#見出し名]]`、`[[ファイル名#見出し名]]`。リンクが書かれた行の所属拠点から、宛先の拠点へ引く | Edge |
| 種別と理由 | 行が `==>`(前提)、`<->`(対比)、`..>`(具体例)で始まり、リンクの後ろに `:` と理由が続く。例: `==> [[フーリエ変換]]: 周波数に分解する前提だから`。全角のコロンも可 | Edge.kind、Edge.reason |
| 霧 | `?`(半角)か `？`(全角)を含む行、または `TODO:`(半角コロン)か `TODO：`(全角コロン)を含む行。URL の中の `?` は除く | Fog(所属拠点と行番号を持つ) |
| 孤島 | ほかの島(ファイル)と、道で 1 本もつながっていない島(ファイル)。見出しの親子の道は数えない。ファイルの最初の見出しに isolated を付ける。地図全体で判定する | Node.isolated |
| リンク切れ | 宛先が存在しない内部リンク | 目印(Edge は作らない) |

**リンクの解決:** 同名のノートが 1 つだけなら `[[ノート名]]` で解決する。別フォルダに同名があるときは `[[大学用/授業/科目A/ノート名]]` のようにフォルダ名を付ける。同名が複数あって決まらないリンクは、リンク切れの目印として扱い、表示文を「この道の先が、複数あります」にする。別のフォルダの拠点を結ぶ道は、MVP 後に橋として描くため、Edge にフォルダをまたぐかどうかの印を持たせておく。

**見出しの親子:** 同じファイルの中で、親の見出しとその下の見出しは、自動で道でつなぐ。ファイルの最初の見出しがそのファイルの代表で、ほかの最上位の見出しもそこにつなぐ。この道は Edge の auto に true を付ける。

**ファイルへのリンク:** `[[ファイル名]]` は、そのファイルの最初の見出しにつなぐ。見出しより前に書いたリンクも、ファイルの最初の見出しの所属にする。見出しがないファイルは、ファイル名を拠点の名前にして 1 つの拠点とする。

**データ構造:**

```
Node { id, file, title, level, line, typedChars, isolated }
Edge { from, to, kind(前提|対比|具体例|未指定), reason, crossFolder, auto }
Fog  { node, line, text }
Mark { type(理由なし|リンク切れ|孤島), target }
```

**再解析のタイミング:** 入力が止まって 0.5 秒後に、変更のあったファイルだけを再解析し、マップへ差分を反映する。

## マップ表示仕様

マップは、解析結果(Node、Edge、Fog)をドット絵風のタイルマップで描き、編集内容を 0.5 秒ほどで反映します。最初の画面は黒いレンガの壁で覆われた真っ暗な状態で、拠点を立てると周りの壁が崩れて土地が見えます。境界はタイル単位です。

| 要素 | 表示 | 備考 |
| --- | --- | --- |
| 暗闇 | 黒いレンガの壁のタイル。画面の初期状態 | まだ何も書いていない領域 |
| 拠点 | 周りの壁が崩れ、タイル単位で土地が開く。開く範囲は typedChars に応じて広がる。typedChars が 0 でも、最低 1 マスは開く | 完成・未完成の区別はしない |
| 道(前提) | 矢印つきの通路 | 一方向 |
| 道(対比) | 二重の通路 | 向きなし |
| 道(具体例) | 細い通路 | |
| 道(つながった時) | 2 つの土地の間の壁が崩れ、通路が開く | |
| 霧 | 開けた土地の中の半透明の霧のタイル | 書き直して解消すると晴れる |
| 孤島 | 暗闇の中に、離れて開いた土地。マップの外周に置く | リンクがつながると、間の壁が崩れて中心側へ寄る |
| 目印 | 道や拠点に付く小さな「!」。クリックすると 1 文で内容を表示する | 一覧や通知は出さない |
| 花 | 開けた土地の中に咲く小さな花。色と形は感情の種類を表す | 詳細は「感情の花の仕様」 |
| 建物 | 別名が書かれた拠点の土地に建つ。大きさは、別名の出現回数と、エディタでの強調の強さ(見出し内が強、太字が中、通常本文が弱)から決まる。小屋・家・ロッジ・ビルの順に大きくなる | 点数と段階は Resources/MapConfig/buildings.json(仮の値)。固有名詞ノートの先頭行「別名: 田中, たなか」で定義する。ホバーで名前と回数を表示。新しく建つ時は下から伸びる |
| 自然物 | 木・低木・岩・キノコ・切り株・芽・草が、土地に自動で置かれる。本文量が多いほど草・芽から低木・木へ増え、リンクの道沿いには岩や低木、見出しの階層と町(フォルダ)で樹種が変わる | 密度と対応は Resources/MapConfig/nature.json(仮の値)。「拠点 ID + 通し番号」から決めるので、解析のたびに景色が変わらない。花・旗・目印・建物と重ならない |

**配置:** 力学モデル(つながる拠点どうしは引き合い、全体は反発し合う)で位置を決め、タイルの格子に合わせて丸める。外部の描画ライブラリには依存しない。

**操作:**

- ドラッグで移動、ホイールで拡大・縮小(タッチはドラッグとピンチ。実機では未確認)
- 拠点のダブルクリックで、エディタを分割し、今のノートを残したまま、その拠点のファイルを該当する見出しの位置で開く。1 回のクリックは選択だけ
- 建物のダブルクリックで、固有名詞のノートを分割して開く。ホバーで名前と出現回数を出す

**エディタとの連動(マップからエディタへの編集操作はない):**

- エディタのカーソルがある見出しの拠点を、金色の枠で示す(クリックで選んだ拠点とは別の表示)
- その拠点が画面の内側 20% の余白より外にあれば、約 0.25 秒で中央へ自動スクロールする。ズームは変えない。マップを操作している間と、最後の操作から 3 秒間は動かさない。ノートを切り替えた時も、そのノートの先頭の拠点へ移る
- 見出しを追加した時は、その拠点の土地の壁だけが崩れる(文字が増えて土地が広がる時は崩さない)。見出しの書き換えは追加ではなく、位置を引き継ぐ
- 拠点の位置は `.cartograph/map-layout.txt` に保存し、次に開いた時に復元する。見出しを書き換えても、同じファイルで並びとレベルが一致する拠点は位置を引き継ぐ

**性能の目標:** 拠点 500 個、道 1,000 本で 30 fps 以上。

**実測(Unity エディタの再生モード、合成データ 500 拠点・道 1,000 本・建物 63 棟、ビルドした実機では未測定):** 全体表示 45.8 fps、拡大率 0.3 で 35.7 fps、拡大率 1.0 で 59.5 fps(最適化前は 12.6 / 29.1 / 55.1 fps)。解析結果を受けての更新は約 115 ms(位置の再計算を省いた後)。引いた時は土地を 1 マス 1 ピクセルの絵 1 枚で描き、近づくとマスごとの絵に切り替える。計測は `MapProfile`(`Enabled` を true にする)と `MapBenchmark` で再現できる。

**見た目の差し替え:** タイル画像と色は設定ファイルとフォルダに集める。MVP は単色の仮タイルで動かし、ドット絵の素材ができた時に差し替える。

**MVP 後:** フォルダ階層のズーム表示(引くと上位の町、寄ると科目の中の拠点)と、フォルダをまたぐ道を橋として描く表現。固有名詞の建物は実装済み(上の表)。別名は最長一致で検出し、1 文字の別名は前後が漢字の時は検出しない。サイズは 32 の倍数で自由で、ビルだけ部品式(屋上・中階の繰り返し・1 階)で縦に伸ばし、それ以外は固定サイズの 1 枚絵。素材の詳細は Docs/designer-brief.md。

## 本文量と目印の仕様

拠点ごとの本文量(typedChars)を数えて、土地の広さで見せます。完成・未完成の閾値は設けません。リンクまわりの 3 つの状況は、マップ上の小さな目印で知らせます。一覧や通知は出しません。

| 目印 | 出る場面 | 表示文(案) |
| --- | --- | --- |
| 理由なし | 種別を書いた行(==> など)に「: 理由」がない | この道の理由は、まだ書かれていません |
| リンク切れ | 宛先が存在しない | この道の先は、まだ地図にありません |
| リンク切れ(行き先が複数) | 同名のノートが複数あり、行き先が決まらない | この道の先が、複数あります |
| 孤島 | どこともつながっていない島(ファイル) | ここは、まだどこともつながっていません |

**解析の例:** 次のノートで目印と霧がどう出るかを、テストのサンプルに使う。

```
## フーリエ変換
波を周波数に分けて見る方法。?どこまで厳密に書くか

==> [[波動]]: 重ね合わせで説明できるから
==> [[信号処理]]
..> [[存在しないノート]]: 例として
```

この例では、2 行目の `?` から後ろが霧になる。「波動」への道には理由があるので目印は付かない。「信号処理」への道は理由がないので、理由なしの目印が付く。3 つ目の道は行き先が存在しないので、リンク切れの目印が付く。種別を書かないふつうのリンクには、目印は付かない。

## 感情の花の仕様

感情を表す言葉を書くたびに、その拠点の土地に花が 1 輪咲きます。花の色は、言葉の感情を表します。

| 項目 | 内容 |
| --- | --- |
| 検出 | 感情語辞書の語を、本文の文字列から最長一致で探す。形態素解析は使わない。ラベルが typed の文字だけを対象にする |
| 否定 | 感情語の直後に「ない」「ません」などが続く時は、色を失った枯れた花にする。判定は文字列の一致だけで行う(仮) |
| 短い語 | 辞書の語は 2 文字以上のものだけを使う。1 文字の語の取りこぼしは許容する |
| 咲く数 | 感情語 1 つにつき 1 輪。同じ文の中の同じ語は 1 輪にまとめる(仮) |
| 咲く場所 | その拠点の土地の中。位置は、本文中の行の位置に対応させる(仮) |
| 感情の分類 | 喜・怒・哀・楽の 4 種。辞書の語を増やして、あとで種類も増やせる |
| 色 | 初期値を用意し、利用者が変えられる。喜 = 黄、怒 = 赤、哀 = 青、楽 = 橙(仮)。形も感情ごとに変え、色の区別がつきにくくても見分けられるようにする |
| 消える時 | 感情語を消すと、その花も消える。解析をやり直して、花を作り直す |
| 辞書 | 喜・怒・哀・楽ごとに、数十〜数百語を自作する。足りなければ、あとで公開されている辞書を足す(その時に利用条件を確認する)。形式は、語と感情の分類を並べた CSV(仮) |
| 設定 | 色の対応は `settings.json` に保存する |

**データ構造:**

```
Flower { node, line, word, emotion }
```

## 実装順序

M0 の技術検証でテキスト欄の可否を先に確かめ、M1 から M6 を順に進めます。M7 は、MVP に入れるかを決めてから着手します。各マイルストーンは Claude Code への 1 回の依頼単位で、受け入れ条件を満たしてから次へ進みます。

| 段階 | 内容 | 受け入れ条件 |
| --- | --- | --- |
| M0 技術検証 | UI Toolkit のテキスト欄で、貼り付けの遮断、日本語 IME の入力、1 万字の入力遅延、元に戻す・やり直しを試す小さな試作を作る | 4 項目の結果を表で報告する。実現できない項目があれば、代替案(自前エディタ)と工数の見込みを示す |
| M1 ファイルとエディタ | プロジェクトフォルダを開く、フォルダ階層とファイル一覧、Markdown の編集と保存 | 再起動後も内容が残る。ネットワークなしで動く。3 階層の入れ子のフォルダが、一覧に階層のまま出る |
| M2 入力制御と履歴 | 入力制御仕様と履歴ログを実装し、来歴を再構築する | 外部のテキストの貼り付けが、キーボード操作と右クリックの両方で遮断される。内部コピーの貼り付けは通り、元のラベルを引き継ぐ。履歴を再生した結果が本文と一致するテストが通る |
| M3 解析 | 解析仕様のパーサを、Unity に依存しないアセンブリで実装する | 5 本のサンプルノートで、拠点、道、霧、孤島、リンク切れが期待どおりに出るテストが通る。見出しの親子の道、ファイル名リンクの宛先、履歴のないノートの扱いも確かめる。コードブロック内と URL 内の `?` は無視される |
| M4 マップ表示 | マップ表示仕様を、単色の仮タイルで実装する(暗闇、開けた土地、道、霧、孤島)。拠点のダブルクリックで開く分割エディタも作る | 最初の画面が暗闇で、拠点を立てると周りの土地が開く。リンクでつなぐと間の壁が崩れる。編集の停止から約 0.5 秒でマップが更新される。拠点のダブルクリックで、エディタが分割され、該当の見出しが開く。拠点 500 個、道 1,000 本で 30 fps 以上 |
| M5 本文量・目印・花 | 本文量を土地の広さに反映し、3 種の目印と、感情の花を実装する | 自分で打った文字が増えると土地が広がる。貼り付けた文字は数えない。3 種の目印が出て、クリックすると 1 文が表示される。一覧や通知は出ない。感情語を書くと、その拠点の土地に感情の色の花が咲き、消すと花も消える。否定が続く時は枯れた花になる |
| M6 仕上げ | 履歴の書き出しと、自分で使うための整備 | 2 週間の自己使用に入れる状態になる。落ちた時にも履歴が失われない |
| M7 振り返り(MVP に入れるかは未決) | 日ごとの本文量の記録を表示する | 入力履歴ログから、日ごとの文字数と拠点ごとの内訳を表示できる |

**Claude Code への渡し方:** 各依頼には、該当するセクションと受け入れ条件を貼り、「テストは EditMode で自動実行し、結果を報告する」と添える。M0 の結果で本書の「未決・要検証」の箇所を更新してから M1 に進む。

## 未決・要検証

- **履歴と本文のずれ:** 外部のエディタで本文を直した時の扱い。保留。食い違った時に落ちず、本文全体を unknown として扱うことだけは実装する。ずれの検出と補正は実装しない。
- **M0 で確かめること:** UI Toolkit のテキスト欄で、貼り付けと IME 確定を区別できる情報が取れるか。日本語 IME の変換中表示が対象 OS で正しく動くか。1 万字の本文で入力の遅延が出ないか。取れない場合は、自前のテキスト描画によるエディタを検討する(工数が大きく、最後の手段)。
- **日本語入力:** IME の変換中の文字を、本文量にどう数えるか。
- **仮の値:** 0.5 秒、1,000 イベント、30 fps などの数値と、リンクの記法(種別と理由、フォルダ名つきのリンク)は仮の取り決め。M0 以降で調整する。
- **ドット絵の細部:** 色数と花の 4 種の形(デザイナーの提案待ち)。タイルは 32×32 px、アニメは 8 コマ(4 列×2 行)に仮決定。ただし旗は 64×64 px、花は 32×64 px(縦長。1 コマの大きさ。花のシートは 128×128 px。枯れた花は 32×32 px)。素材の詳細は Docs/designer-brief.md。
- **感情語の辞書:** 喜・怒・哀・楽ごとの語を自作する。M5 の前に最初の版を用意する。足りなければ公開辞書を足す(その時に利用条件を確認する)。
